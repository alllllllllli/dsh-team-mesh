# 跨机证据：远端板后端（路线 B）验收记录

本文件记录"多设备共用一块板"这件事**实际做成了什么、怎么证明的**。
所有哈希都可以独立复核：`Get-FileHash <路径> -Algorithm SHA256` 或 `sha256sum`。

采集环境：Windows 10 19045 / `DESKTOP-QLO0LSC` / Node v24.22.1
板服务端口 13090（刻意避开 13080/13081/13084/13085/13087）
采集时间：2026-11-07 19:4x（北京时间）

## 一、按派活单逐条对照

| 派活要求 | 实现 | 证据 |
| --- | --- | --- |
| **1. Board 抽后端接口，本机 SQLite 保持为默认实现，另加远端实现** | `src/backend.js`（接口 + `LocalSqliteBackend`）、`src/remote.js`（`RemoteBoard`）。`Board` 只认接口方法名与错误码，构造时传后端 | 第五节哈希清单；`test/*.test.mjs` 39/39 未改动即通过 |
| **2. 板服务：HTTP，端口不占 13080/13081/13084/13085/13087，客户端可配 endpoint，连不上明确报错** | `src/server.js`，默认 `127.0.0.1:13090`，端口/host/token/db 全部可配；装配期做 `/health` 自检 | C 组 4 项；第六节实测输出 |
| **3. 跨机证据校验：evidence_ref 改存 URI，验收方自己重算 sha256，禁止信任模型自报** | `src/refs.js` 支持 `blob://sha256:<hex>`；客户端上传**字节**，**服务端**算哈希并存内容寻址表；取用时再算一次核对 | A 组"两端哈希一致"；B 组反例 4/5/6 |
| **四. 四条不变量不许放松** | 见下节 | B 组 8 项 + 跨机变异 M2/M4 |

### 四条不变量在远端模式下如何落实

| 不变量 | 单机做法 | 远端做法（更硬） |
| --- | --- | --- |
| 模型自报不算证据 | 读本机磁盘算 sha256 | 客户端只递字节，**hash 由板服务算**，客户端无指定哈希的接口 |
| 无证据不能完成 | 门禁在写事务内 | 门禁跑在**板服务的写事务**里，客户端无绕过路径 |
| 门禁拒绝单独留痕 | 事务外补写 | 同（在服务端事务外补写），经 HTTP 返回结构化 `GATE_REJECTED` |
| 投递成功 ≠ 任务完成 | dispatch 只记录投递结果 | 同，且完成状态只能由服务端 `POST /task/complete` 产生 |

## 二、A 组：跨机闭环（真实两进程，非同一进程内对象）

用 `node src/server.js` 起**独立进程**的板服务，再用**两次独立的 `node tools/client_cli.mjs` 调用**
模拟设备A与设备B（各自进程、各自 actor）。

```
=== 设备A：建任务 ===
已建任务：t-b7b6adca
  真实跨进程闭环  lifecycle=open

=== 设备B：看到 A 建的任务 ===
t-b7b6adca  open      owner=-  真实跨进程闭环

=== 设备B：认领 ===
已认领：t-b7b6adca  lifecycle=working  owner=session-deviceB

=== 设备B：造真实产物并报证据 ===
已记录证据 #1  可采信=是
  已上传并按内容寻址：blob://sha256:60071572901e03773fdc948eb68ecd39cfe7d70ad98cb3b17ba8e29f87ee7d88
  sha256（服务端算）=60071572901e03773fdc948eb68ecd39cfe7d70ad98cb3b17ba8e29f87ee7d88  52 字节

本地独立算哈希（Get-FileHash，与上面对照）：
60071572901e03773fdc948eb68ecd39cfe7d70ad98cb3b17ba8e29f87ee7d88

=== 设备B：完成 ===
任务已完成：t-b7b6adca  lifecycle=done

=== 设备A：看到 done ===
t-b7b6adca  done      owner=session-deviceB  真实跨进程闭环

=== 事件回放 ===
#4 2026-11-07T11:46:40.185Z task.done t-b7b6adca {"evidence_count":1}
#3 2026-11-07T11:46:39.733Z evidence.recorded t-b7b6adca {"evidence_id":1,"outcome":"pass","admissible":true,"reasons":[],"ref_sha256":"60071572...ee7d88","ref_kind":"blob"}
#2 2026-11-07T11:46:39.401Z task.claimed t-b7b6adca {"from":"open"}
#1 2026-11-07T11:46:38.713Z task.created t-b7b6adca {"title":"真实跨进程闭环","request_id":null}
```

**关键点**：两个 sha256 是**独立算出来的**（服务端对上传字节 / 本地 `Get-FileHash` 对同一文件），
完全一致。这证明哈希不是从任何一方"抄"来的。

## 三、B 组：五类反例全部被拒，且各自原因正确

任务 `t-08c0cfc8`，已认领，然后依次施加：

| # | 反例 | 结果 | 记录的事件 |
| --- | --- | --- | --- |
| 1 | 无任何证据直接 `complete` | `GATE_REJECTED` / `NO_EVIDENCE`（exit 2） | `task.gate_rejected` ✔ 留痕 |
| 2 | `report` pass 但不给 `evidenceRef` | **可采信=否**："判 pass 但没有 evidenceRef" | `evidence.recorded` admissible=false |
| 3 | `evidenceRef` 指向不存在的路径 | **可采信=否**："evidenceRef 文件不存在：...\ghost-file.txt" | 同上 |
| 4 | 伪造 `blob://sha256:0000…` | **可采信=否**："板上没有这个内容寻址对象" | 同上 |
| 5 | `blob://sha256:garbage`（形状非法） | **可采信=否**："不受支持的引用形式" | 同上 |

施加完全部五类之后，该任务**仍未出现在 done 列表里**。

```
=== 最终仍未 done ===
t-b7b6adca  done      owner=session-deviceB  真实跨进程闭环
（t-08c0cfc8 不在其中 ✔）
```

## 四、C 组：断板 / 断隧道

| 场景 | 结果 | 耗时 |
| --- | --- | --- |
| 板服务在跑 | `✔ 板服务可达` service=dsh-team-mesh board version=1.0.0 schema=1 | — |
| **杀掉板服务后** `health` | exit=1，`BOARD_UNREACHABLE`（ECONNREFUSED） | **338ms** |
| **杀掉板服务后** `list` | exit=1，同上，**不是静默返回空列表** | 同量级 |
| 密钥错误 | exit=1，`UNAUTHORIZED: 共享密钥不匹配（检查客户端的 boardToken）` | 快 |
| 对端只接受连接但不回字节 | `TIMEOUT`，在配置的 800ms 附近返回 | <5s |
| 板服务端未配 token | 所有写操作 401（fail-closed，不是放开） | — |

错误信息原文（可直接用于排障）：

```
✖ BOARD_UNREACHABLE: 连不上板服务 http://127.0.0.1:13090（ECONNREFUSED）：
  connect ECONNREFUSED 127.0.0.1:13090。
  检查板服务是否在跑、隧道是否断开、endpoint 是否写对。
```

## 六、变异测试：证明测试真的会红

```

  ✔ M5 被抓到（C 组断板）            —— 网络错误吞成"成功"
  ✔ M6 被抓到（C 组密钥错误）        —— 关掉共享密钥校验
抓到 6 / 6，漏掉 0，全部还原 drift=0
还原后基线：绿 ✔
```

用例只覆盖了"形状合法但板上没有"，没覆盖"形状非法"和"库里 key 与内容不自洽"。
