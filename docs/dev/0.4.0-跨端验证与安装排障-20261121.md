# 0.4.0 跨端验证与安装侧排障记录（2026-11-21）

本文记的是**装在别的机器/别的 profile 上跑起来之后**才暴露的问题，以及一轮跨端验证的结果。
**源码零改动**：文中所有结论都不需要改 `src/`，仓库内容本身无需更新。

结论三条：

1. **有一个安装侧真故障**：安装副本缺 `src/dispatcher.js`，插件 `enabled: true` 但 `fiberPhase: null` —— 等于压根没起来。补回同哈希文件 + toggle 一次即 `active`。
2. **`team.db` 的 `task` 表是空的**，478 条全是 `peer.event`。原因是本轮工作项建在 DSH 原生 agent-team 板（进程内），**不是** mesh 的 SQLite 板 —— 两个板子，别混。
3. **只读导出侧**能正常工作（面板类前端消费它），但事件文本是原始 payload JSON，未做可读化。

---

## 1. 安装侧故障：`fiberPhase: null`

### 现象

`plugin_manager list_plugins` 里：

```
include:dsh-team-mesh   enabled: true   fiberPhase: null
```

同时有一条 `Cannot find module` 的告警，路径指向安装副本里的 `src/dispatcher.js`。

**关键点：`enabled: true` 不代表插件起来了。** 判断"到底起没起"只看 `fiberPhase`：`active` 才算激活，`null` 是 fiber 压根没建。

### 判定三步

1. 读 `fiberPhase`，不要只看 `enabled`；
2. 从告警里取**绝对路径**，确认缺的是哪个文件（告警只有一次，容易被后面的日志冲掉，要在启动日志里往前翻）；
3. 拿**源目录**和**安装副本**逐文件比 **SHA-256** —— 比文件名、比大小都会漏（本轮缺文件时目录看起来"差不多全"）。

本轮现场结果：源目录 `src/` 与安装副本逐文件比对，**只差 `dispatcher.js` 一个文件**，其余哈希全等。

### 处置

```powershell
# 1) 只补缺的那一个文件，不要整目录覆盖
#    （整目录覆盖会顺带盖掉别人在副本上改过的东西）
Copy-Item <源目录>\src\dispatcher.js <安装副本>\src\dispatcher.js

# 2) 回读哈希，确认补对了
Get-FileHash <安装副本>\src\dispatcher.js -Algorithm SHA256
```

- 补回的 `src/dispatcher.js`：23 799 B，`B4133DEEA7FAC99CF0CBD84C05ED58E82AF7720E4D538FF8DDF940204FE73CD5`
  **与仓库内 `src/dispatcher.js` 逐字节一致**（2026-11-21 复核）。
- 然后 toggle 一次触发重新加载：`plugin_manager set_plugin(include:dsh-team-mesh, enabled=false)` → 再 `enabled=true`。
- 复查：告警为空，`fiberPhase: "active"`。

**不需要重启 DSH 进程。** toggle 会重新走一遍插件加载，改动当场生效。

### 预防

- 装完（含升级后）**必须回读 `fiberPhase`**，`enabled: true` 不作为验收依据；
- 升级走「整目录替换 + 回读校验」，别挑文件拷 —— 本轮就是挑文件拷漏了一个；
- 目录里多一个 `.bak`、少一个 `.js` 都不会报错，只有 fiber 起不来 —— 交付前跑一次逐文件哈希比对最省事。

> 根因未定位到具体操作步骤（哪个命令漏拷的），只能确认结果。这类"缺一个文件"的故障不重复问根因，靠回读校验兜住即可。

## 2. 板库现状：`task` 表 0 行

`$DSH_HOME\team\team.db`（默认 `%USERPROFILE%\.dsh\team\team.db`）：

| 表 | 行数 | 说明 |
|---|---|---|
| `task` | **0** | 没有任务卡 |
| `peer.event` | 478 | 全部 `task_id IS NULL` |

事件形状（`peer.event`）：

```json
{"task":"","at":1794651572825,"kind":"peer.event","node":"<节点名>","text":"<原始 payload JSON>"}
```

顶层键：`["tasks","events","nodes"]`。

**为什么是空的**：本轮的工作项建在 DSH **原生 agent-team 板**（`@deepseek-ai/dsh-agent-team`，进程内，落盘位置未定位），而 mesh 的板是独立的 SQLite 文件。两套板子并存，读数前先确认自己在看哪一个 —— 拿 mesh 的 `team.db` 去印证原生板上的任务，一定得到"0 行"。

**只读导出的待改进项**：`text` 直接是 `peer.event` 的原始 payload JSON，478 行读起来很吵。可加一个 `--compact-events` 之类把 payload 压成一行摘要；本轮未做。

## 3. 没验证什么（不粉饰）

- **没有在真实 GUI 里目视确认过渲染**：面板类前端只验到 HTTP 路由层（页面 200、快照 200/204/502、路径逃逸 403、缺文件 404 五条路径全通过），排版是否正常需要人看一眼。
- **只读导出只做过短跑验证**：`--watch` 模式未做长时间运行与并发写库压测。
- **本轮没有重启生产实例做端到端复验**：`fiberPhase: active` 是 toggle 后读到的，重启后是否会再次掉回 `null`（即缺文件的问题是否已被彻底消除）未跟踪。
- **安装侧根因未定位**（见上）。
