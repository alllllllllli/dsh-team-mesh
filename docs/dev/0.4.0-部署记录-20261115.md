## 一、生产板服务（server）——已重启并生效

### 做了什么

1. 部署前记录状态：`/health` 可读（旧版无 0.4 新段）、板进程存在。
2. 停掉旧板进程（计划任务 `dsh-team-board` 停 → 等旧 node 进程退出，确认板进程数为 0）。
3. `Start-ScheduledTask dsh-team-board` 拉起新代码，轮询 `/health` 直到 `ok=true`。
4. 观察新 `/health` 的 0.4 字段；等待一个 sweep 周期后复核 GC 结果。

### 复跑/复核命令（只读，在板服务主机上执行）

```powershell
# 1) 健康与 0.4 新段
Invoke-RestMethod 'http://127.0.0.1:13090/health' | ConvertTo-Json -Depth 6

# 2) 板进程与启动时间
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -match 'src[\\/]server\.js' } |
  Select-Object ProcessId, CreationDate

# 3) 计划任务状态
Get-ScheduledTask -TaskName 'dsh-team-board' | Select-Object TaskName, State

# 4) 审计目录（按天滚动 JSONL；只列文件，不打印内容）
Get-ChildItem 'C:\Users\admin\.dsh\team\audit' -ErrorAction SilentlyContinue |
  Select-Object Name, Length, LastWriteTime

# 5) 等 1 个 sweep 周期（默认 60s）后再看 gc/sweep 计数
Start-Sleep -Seconds 70
(Invoke-RestMethod 'http://127.0.0.1:13090/health').gc
(Invoke-RestMethod 'http://127.0.0.1:13090/health').sweep
```


- 回滚只还原 `src`；新增的测试/文档可保留（不参与运行）。
